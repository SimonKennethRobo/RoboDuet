# 四足机器人全身 SE(3) 轨迹跟踪：项目设计文档 v3

> **范围**：平地、自由空间（末端不碰东西）、通用 SE(3) 末端轨迹跟踪。base 速度命令由系统自主生成，不由人遥控。
>
> **架构**：双 policy（WTW 风格的腿部 policy + 上层的臂/协调 policy），上层叠加阻尼最小二乘逆运动学（DLS-IK）的残差。

---

## 0. 三句话总结

1. **Base 该往哪走是算得出来的**：给定任意一条末端轨迹，我们可以用纯运动学几何即时算出 base 的前馈速度，不需要 RL 去学"base 该怎么动"。
2. **Policy 学的是"怎么走"而不是"往哪走"**：姿态调节、步频变化、动力学补偿——这些涉及复杂耦合的维度交给学习，但 base 的大方向已经由解析计算给定了。
3. **一个 checkpoint 覆盖任意轨迹和任意时间约束强度**：轨迹的几何形状和速度要求分开表示，时间约束的松紧度（τ）作为 policy 的输入，部署时可调。

## 0.1 关键术语速查

在正文开始前，先解释本文反复出现的几个术语，方便查阅。

**EE（End-Effector，末端执行器）**：机械臂最前端的部件（夹爪/工具）。它的位置和朝向就是我们要控制的对象。

**SE(3)**：三维空间中的刚体位姿，包含位置（3个自由度）和姿态/朝向（3个自由度），一共 6 个自由度。"全 SE(3) 跟踪"意味着 EE 不仅要到正确的位置，还要摆到正确的朝向。

**base**：四足机器人的身体/躯干。它可以在地面上移动（前后左右走），也可以改变自己的姿态（蹲下、前倾、侧倾等）。

**WTW（Walk These Ways）**：一种四足运动 RL 方法。它的特点是把 base 的高度、俯仰角、步频等行为参数做成**命令通道**——你输入"降低 5cm"，它就降低 5cm，输入"加快步频"，它就加快步频。这种可预测的行为对上层控制器非常重要。

**ρ（rho，归一化伸展度）**：衡量"机械臂有多费劲"的一个 0 到 1 的数字。ρ 接近 1 表示臂快伸直了，没余量；ρ 接近 0 表示目标太近，手肘折叠，也很别扭；ρ 在 0.35-0.85 之间是舒适区。

**v_ff（feedforward velocity，前馈速度）**：通过解析计算得出的"base 应该以什么速度往哪个方向走"的参考值。policy 不需要从零学习 base 运动方向，只需要在 v_ff 基础上做小修正。

**DLS-IK（Damped Least Squares Inverse Kinematics，阻尼最小二乘逆运动学）**：已知末端要去哪个位姿，算出关节应该转多少度。"阻尼"是为了在接近奇异构型时输出不会爆炸。

**奇异构型**：机械臂的某些姿态下，末端在某个方向上完全丧失了控制能力。最直观的例子是胳膊完全伸直——此时无论怎么转关节，指尖都没法再往正前方多伸一毫米。

**课程学习（Curriculum Learning）**：训练时逐步增加任务难度。先给简单的轨迹，policy 学会后再给难的。类似于教小孩先学走再学跑。

肩膀： 机械臂到四足的mount link

## 1. 为什么这个问题和四足运动的问题本质不同

本节解释本项目与传统四足 RL locomotion 的根本区别。理解这个区别，后面所有设计决策都会顺理成章。

### 1.1 主线对比

四足 RL locomotion（纯走路）面对的核心挑战是**外部世界不可观测**：地面是什么材质、多滑、有没有坑、有没有石头——这些 policy 看不到，必须靠估计和鲁棒性来应对。所以 locomotion 领域这几年的重点都在做各种隐状态估计器（privileged training、teacher-student、RMA 等）。

加了机械臂之后，问题变了。主要的扰动不再来自外部世界，而是来自**机械臂自己**——臂一动，重心偏了，惯量变了，对 base 施加了反作用力。但关键是：**这些扰动全是已知的**。关节角已知，角速度已知，甚至未来要去哪都已知（参考轨迹就在手上）。

所以：

- **Locomotion**：在不可观测的外部世界里保持鲁棒（核心是估计）
- **Loco-manipulation**：在已知但强耦合的自身动力学里维持精度（核心是协调和前馈）

在本项目的设定下（平地 + 自由空间），这一点更极端：没有未知地形、没有外力、没有未知载荷。**系统里不存在需要估计的隐状态。** 所有的预算都应该投入协调和精度。

### 1.2 三条直接推论

**推论 1：臂的 sim2real 策略和腿不同。**

Locomotion 里，Domain Randomization（DR）越猛越好——反正任务容差是"别摔"，DR 不会伤害任务。但 manipulation 要 cm 级精度。对臂的运动学/动力学做 DR，**直接向 EE 误差中注入不可消除的噪声**，policy 的最优策略会退化成"保守地停在误差球心不动"。

正确的做法是：**臂的参数（连杆长度、零位、减速比、执行器模型）靠系统辨识标定，不做 DR；腿和地面的参数照常 DR。** 双 policy 架构在这里恰好提供了一个天然的划界——两个 policy 各自使用不同的 sim2real 策略。

**推论 2：base 状态估计的漂移会直接变成跟踪误差。**

Locomotion 的命令是速度（"往前走 0.5m/s"），里程计漂移不会积分进任务。但轨迹跟踪的命令是位姿（"EE 应该在这个位置、这个朝向"），base 位姿估计漂了 1cm，EE 误差就多 1cm，还会被力臂放大。

对策：目标一律在 **base 的局部坐标系**里表达，避免使用世界坐标系。

**推论 3：不能对 base 的高度、俯仰角等加惩罚。**

标准 locomotion RL 代码（如 legged_gym）里，base 的高度偏离默认值会被惩罚，俯仰角偏离零会被惩罚。但在 whole-body 操作中，**这些恰好是扩展工作空间的关键自由度**——降低 base 高度可以让 EE 够到更低的目标，前倾可以让 EE 伸得更远。加了惩罚就等于把这些能力堵死了。WTW 在这里天然占优：它把 base 高度/俯仰做成**命令跟踪项**而不是惩罚项。

## 2. 整体架构

### 2.1 为什么是双 policy

系统有三个时间尺度：

| 层            | 需要的更新频率 | 说明                         |
| ------------- | -------------- | ---------------------------- |
| 臂的精确控制  | ~200 Hz        | 需要高带宽才能实现 cm 级精度 |
| 腿的步态      | ~50 Hz         | 标准四足控制频率             |
| 姿态/步频调节 | 1–5 Hz        | 这些是慢变量，必须限速防抖   |

单 policy 只能选一个频率。选 50Hz 的话臂的精度上限被锁死；选 200Hz 的话腿的训练成本暴涨，而且 policy 没有理由不在 posture 通道上高频抖动。双 policy 让每层运行在最合适的频率上。

另外，WTW 的设计哲学恰好使它成为一个理想的"可预测插件"——它的行为被命令通道钉死了，上层可以准确预测"我发了这个速度命令，base 会怎么动"。普通的 locomotion policy 的行为是涌现的，同一个速度命令在不同情况下响应不同，上层很难学到稳定的逆模型。

### 2.2 两个控制环不能同时根据 EE 误差行动

这是本项目最重要的架构约束，值得用一个例子详细解释。

假设 EE 目标在右前方。如果**两个**环路都根据 EE 误差来行动：

1. EE 目标移到右边 → 臂立刻往右伸（快，几十毫秒）
2. 同时，base 也收到"往右走"的命令（慢，几百毫秒）
3. 臂已经补偿完了，EE 到位了
4. 但 base 还在往右走（它慢，刚起步）
5. base 到位后，把臂连带着推过了头 → EE 跑过了目标
6. 臂反向补偿 → base 收到反向信号 → **来回振荡（极限环）**

更隐蔽的失败模式：不振荡，但 base 永远不动。因为臂总能补上，base 收到的误差信号永远接近零 → 退化成"decoupled"（base 不动 + 臂拼命伸），臂长期在极限位形工作。

**解决方案：让两个环路负责不同的目标。**

- **臂**负责 EE 在 task space 的误差（快、精确）
- **base**负责维持机械臂的工作余量（慢、只关心"臂是不是快够不着了"）

base 环的驱动信号是 ρ（可达性余量），不是 EE 误差。ρ 的定义里不包含 EE 的当前位置（它只看目标和肩膀的距离），所以两个信号在定义上就是正交的。

### 2.3 腿部 Policy 的响应需要可预测

上层 policy 需要知道"我发了速度命令 v_cmd，base 实际会以什么速度运动"。如果腿的响应在不同情况下差别很大，上层只能做最保守的决策。

训练腿部 policy 时，除了标准的速度跟踪 reward 外，额外加一个**响应一致性**约束：定义一个简单的一阶参考模型 `v̇_ref = (v_cmd - v_ref)/T`（就是一个带时间常数 T 的低通滤波器），惩罚实际速度偏离这个参考模型的程度。T 大约 0.3-0.5 秒。

效果是：无论臂在做什么、载荷多大、posture 怎么变，腿的速度响应都近似一个线性系统。这让上层可以准确预测 base 的运动。

配套：把 `v_actual - v_cmd`（速度跟踪残差）喂给上层观测。上层知道"腿没完全听我的话"，可以据此调整。

### 2.4 上下层之间需要双向信息

腿的步态产生周期性的 base 起伏（每一步 base 都会上下和前后晃一点，频率 2-4Hz）。如果上层只有当前 base 状态，它只能**等 base 晃了之后再反应**——导致 EE 在步态频率上有肉眼可见的抖动。

解决办法：把步态传给上层。步态告诉上层"现在是摆腿的哪个阶段"，上层可以提前预知 base 马上要往哪个方向晃，直接前馈抵消，不用等它发生。

完整的双向接口：

| 方向       | 传递的信息                                         |
| ---------- | -------------------------------------------------- |
| 上层 → 腿 | 未来的 CoM 偏移 / 惯量变化 / 臂的参考轨迹摘要      |
| 腿 → 上层 | 足端接触状态、base 姿态短期预测、v_actual − v_cmd |

### 2.5 WTW 剪裁

WTW 原版支持多种步态（trot、pace、bound、pronk）。但步态多样性对上层 policy 是**负债**而不是资产：

- 每种步态的扰动频谱不同，上层要学多套补偿策略
- 步态切换时的瞬态扰动几乎无法用相位前馈预测
- 网络容量被分散到用不到的步态上

本项目**固定使用 trot 步态**。保留的命令通道：

| 通道                                      | 是否保留      | 理由                     |
| ----------------------------------------- | ------------- | ------------------------ |
| body height / pitch / roll / stance width | ✅ 全保留     | 扩展工作空间的核心手段   |
| 步频                                      | ✅ 保留，限速 | 适配不同行走速度         |
| 足摆高度                                  | ✅ 保留       | 适配不同速度             |
| 步态类型                                  | ❌ 固定 trot  | 多步态对跟踪精度是净负面 |

### 2.7 v_ff 不是让 policy 凭空生成的，是算出来的

这是本项目和之前方案的最大改动。详见 §5 "在线 Base 前馈"。简单来说：给定末端轨迹和当前 base 位置，存在一个纯几何计算可以即时算出"base 应该以什么速度往哪走"。policy 只需在这个计算结果上做小残差修正。

### 2.8 IK 与残差 Policy 的配合

几个原则：

1. **IK 在 base 坐标系下求解**。如果在世界坐标系下解，base 位姿估计的漂移会 1:1 灌进 IK 输出并被力臂放大。在 base 坐标系下解，漂移的影响被隔离到"目标坐标变换"这一处。
2. **残差 Δq 的幅度要限住**。用 tanh 限幅，量级 ~3-5°。放太大 → policy 覆盖掉 IK 的精度先验；卡太死 → 补不了动态项。
3. **必须用 DLS（阻尼最小二乘）而不是纯伪逆**。纯伪逆在奇异点附近输出趋于无穷大 → 残差 policy 面对的被控对象变得不连续 → 训练不稳定。DLS 加了阻尼，输出保持有界。
4. **IK 的 nullspace 和 base 命令不能同时调同一个东西**。IK nullspace 只管关节限位，workspace 层面的冗余全部归 base 命令。

### 2.9 全 SE(3) 约束下机械臂的冗余度问题

6 自由度的机械臂 + 全 SE(3) 目标（位置 3 + 姿态 3 = 6 个约束）→ IK 解唯一（没有多余自由度）→ 零 nullspace。

后果：

1. **manipulability（可操作度）无法靠臂自己改善**。唯一的调节手段是移动 base 或改 posture。这让 ρ 和 posture 通道的重要性显著上升。
2. **腕奇异不可绕过**。没有 nullspace 来躲，只能靠 DLS 阻尼 + base 提前移开。
3. **IK 分支跳变是一个风险**。存在"肘上"和"肘下"两个离散解。如果 IK 在两个解之间跳来跳去，关节角会出现突变，残差 policy 面对的系统变得不连续。对策：用上一步的解做 warm start（热启动），保持分支连续；检测到跳变时给大惩罚。
4. **7-DoF 臂优于 6-DoF**。如果硬件还没定，强烈建议选 7 自由度的臂。

## 3. 轨迹表示：把"走哪条路"和"走多快"分开

### 3.1 为什么要分解

一条末端轨迹 `T_ref(t)` 同时包含两个信息："路径长什么样"和"沿路径走多快"。如果始终把两者绑在一起（一个带时间戳的位姿序列），训练时无法独立调节空间难度和速度难度。

本项目把轨迹分解成两部分：

```
γ(s)     — 几何路径。s 是沿路径走的弧长距离。"这条线长什么样"，不含时间。
s_ref(t) — 时间律。"什么时刻走到多远"。

还原：T_ref(t) = γ( s_ref(t) )
```

这是一个**无损分解**——任何带时间戳的轨迹都能这样拆，拆完可以原样拼回。

它买到的好处：

1. **课程的空间轴和时序轴正交**。"让路径更复杂"和"让速度更快"可以独立调节。
2. **严格时间跟踪和纯路径跟随是同一个公式的两端**。通过一个参数 τ 连续过渡（§3.6）。
3. **preview 按弧长采样，不会因为 policy 减速而缩水**（§5.2 详述）。
4. **停留、急停、目标到达都是同一个数据结构的特例**。"停留 2 秒" = s_ref 有一段平台；"到达目标" = 短路径 + 长平台。

### 3.2 弧长必须定义在 SE(3) 上

如果只用位置计算弧长，会有一个致命问题：EE 停在原地只转腕 → ds = 0 → 这一段被压成了一个点，姿态信息全丢。

正确的弧长定义同时考虑位移和旋转：

```
ds² = ‖dp‖² + λ²‖dθ‖²
```

λ 是一个常数（建议 0.15 m/rad），含义是"1 弧度的旋转变化等价于 0.15 米的平移"。取机械臂操作物体的典型尺寸即可。

**λ 是一个全局设计常数**，在弧长计算、投影度量、preview 采样三处必须保持同一个值。一旦确定就不要改，否则所有课程等级的含义都变了。

### 3.3 从原始数据构造

```python
def to_canonical(p_raw, R_raw, dt, lam=0.15, ds_grid=0.005):
    """把原始位姿序列转成 (γ, s_ref) 的标准形式"""
    # 先滤波：原始噪声是随机游走，会系统性地把总弧长撑大
    p, R = lowpass(p_raw, fc), filter_so3(R_raw, fc)

    # 计算每步的 SE(3) 弧长增量
    dp  = norm(diff(p, axis=0), axis=-1)            # 位移
    dth = so3_angle(R[:-1].T @ R[1:])               # 旋转角度
    ds  = sqrt(dp**2 + (lam*dth)**2)                # SE(3) 弧长增量
    s_of_t = concat([[0], cumsum(ds)])              # 这就是 s_ref(t)
    L = s_of_t[-1]                                  # 总弧长

    # 按弧长均匀重采样，得到几何路径 γ
    s_grid  = arange(0, L, ds_grid)                 # 每 5mm 一个点
    gamma_p = pchip(s_of_t, p, s_grid)              # 位置插值
    gamma_R = slerp(s_of_t, R, s_grid)              # 姿态插值

    return Gamma(s_grid, gamma_p, gamma_R), TimeLaw(t_grid, s_of_t)
```

"在此处停留 2 秒"的信息，全部编码在 s_ref 的平台里（s_ref 不增长 = 没有前进），几何路径对此一无所知。

### 3.4 训练时几何和时间律独立采样

```python
gamma = geometry_generator(level_A)      # 只管形状
s_ref = timing_generator(level_B)        # 只管速度
```

时间律生成器工作在一维标量 ṡ_ref(t) 上——用多个正弦波叠加，通过 softplus 保证非负，再归一化使其刚好走完整条路径。一个参数 f_max 控制时序难度（频率越高 = 速度变化越快 = 越难跟）。

**为什么用频域参数化而不是样条**：直觉上，轨迹的难度不取决于"有多长"或"弯不弯"，而取决于**轨迹的频谱相对于机器人带宽有多宽**。一条 10 米长、大弧度但走得很慢的轨迹是简单的；一条 20cm 但 2Hz 来回的轨迹是困难的。频域参数化让 f_max 直接成为难度旋钮。

### 3.5 运行时 s 从哪来

EE 当前走到了路径上的哪个位置？用**前向窗口投影**：在当前 s 的前方搜索一小段路径，找到离 EE 最近的点。

```python
def update_s(s_prev, ee_p, ee_R, gamma, window=0.15, M=16, lam=0.15):
    """在 s_prev 前方 window 米的范围内，找到 γ 上离 EE 最近的点"""
    candidates = s_prev + linspace(0, window, M)     # 只向前搜索，不回退
    pc, Rc = gamma.p_at(candidates), gamma.R_at(candidates)
    # SE(3) 距离（同一个 λ）
    d2 = ||ee_p - pc||² + (λ · angle(Rc^T @ ee_R))²
    best = argmin(d2)
    return candidates[best], sqrt(d2[best])          # s, 横向误差 d_lat
```

前向窗口同时解决三件事：路径自交时不跳、s 单调不倒退、计算量 O(M) 是常数。

如果横向误差 d_lat 大于阈值 d_max，终止 episode（投影本身失去意义了）。

### 3.6 Time Tube：连续控制时间约束强度

```
timing_err = s - s_ref(t)            # "我走到哪了" 减去 "此时应该走到哪"
```

如果 timing_err > 0，policy 走快了；< 0，走慢了。

**Time tube** 是一个死区：在 |timing_err| < τ 的范围内不罚，超出才罚。τ 是死区半径。

- τ = ∞：完全不关心时间，纯路径跟随
- τ = 0：timing_err 一有就罚，严格时间跟踪
- 中间值：允许一定程度的时间偏差

**τ 不仅是课程变量，还是 policy 的条件输入**。训练时每个 episode 随机采一个 τ，喂进观测。policy 学会根据 τ 调整行为：τ 大时牺牲进度保精度，τ 小时追进度允许稍大的横向误差。

部署时 τ 变成用户旋钮：喷涂任务（要匀速）设 τ≈0，精度优先任务设 τ 大。**同一个 checkpoint。**

实现：

```python
# τ 的编码（压缩到 [0,1) 区间）
tau_obs = tau / (tau + 0.1)          # 0→0, ∞→1

# 每 episode 采样
p = 0.2: tau = 0                     # 严格时间跟踪
p = 0.2: tau = tau_max               # 纯路径跟随
p = 0.6: tau ~ LogUniform(0.01, tau_max)

# 课程控制的是采样分布的下界
# 早期只从 [τ_大, τ_max] 采（不给不可行的时间约束）
# 后期下界降到 0
```

## 4. 可达性：衡量机械臂的"舒适程度"

### 4.1 为什么需要 ρ

仅仅保证 EE 当前能到达目标是不够的。机械臂可能已经接近完全伸直或折叠——虽然还能完成当前任务，但已经没有余量应对任何变化。

ρ 衡量的就是这种"余量"。它不看 EE 跟踪误差（那是臂的事），只看**目标相对于臂工作空间的位置**。base 的 policy 根据 ρ 来决定是否需要移动或调整 posture。

### 4.2 ρ 的定义

```
d = R_shoulder^T · (p_target - p_shoulder)     # 目标在肩坐标系里的位置
r = ‖d‖                                        # 到肩膀的距离
u = d / r                                       # 方向（单位向量）
ρ = r / R_max(u)                               # 归一化伸展度
```

R_max(u) 是"这个方向上臂能伸到的最远距离"。ρ = 1 表示臂伸到了极限，ρ = 0 表示目标就在肩膀上。

舒适带：ρ ∈ [0.35, 0.85]。太大 = 快伸直了；太小 = 太近了手肘折叠。

### 4.3 离线建表

R_max(u) 是一张二维表（水平角 × 俯仰角），离线建好，常驻 GPU。

建表方法：随机采 200 万组关节角 → 正运动学算出末端位置 → 排除自碰和腕奇异严重的构型 → 按方向分格 → 每格取 0.98 分位数 → 高斯平滑。

关于"排除腕奇异"：我们计算旋转子雅可比矩阵 J_rot 的最小奇异值 σ_min。σ_min 衡量的是"在最差的方向上，关节运动能在多大程度上产生末端旋转"。σ_min 接近 0 意味着手腕几乎无法在某个方向上旋转了——虽然位置上够得着，但姿态自由度已经丧失。我们把这类构型从建表数据中排除。

取 0.98 分位数而非最大值：最远距离对应的构型恰好是臂完全伸直的奇异构型，我们不希望把那当作"可用距离"。0.98 分位天然留了裕度。

最后做高斯平滑：ρ 进 reward，表不连续会导致 reward 梯度不连续，影响训练稳定性。

### 4.4 双边软 barrier

```python
r_reach = -( softplus((rho0 - rho_hi) / beta) + softplus((rho_lo - rho0) / beta) )
```

ρ 在舒适带内 → 惩罚接近零。ρ 往外冲 → 惩罚迅速增大。beta 控制过渡的陡峭程度。

### 4.5 ρ 是怎么和 posture 连起来的

base 的姿态（高度、俯仰角、侧倾角）直接改变肩膀在空间中的位置：

- 降低 base 高度 → 肩膀下移 → 低处目标的 ρ 变小（更舒适），高处目标的 ρ 变大
- base 前倾 → 肩膀前移并上移 → 远处高处目标的 ρ 变小

这意味着 posture 命令就是调节 ρ 的执行器。而且这个关系是解析可微的——ρ 对 posture 的导数可以直接算出来，不需要学习。

**重要限制**：高速行走时，可行的 posture 范围更窄（跑步时不能蹲太低）。上层如果不知道这个限制，会命令不可行的 posture。对策：在接口处做速度条件化的截断（velocity-conditioned clamping）。

### 4.6 如果 2D 表不够：4D 表

ρ 的 2D 表只看目标的位置方向，不看目标要求的姿态。同一个位置，工具朝前很轻松，工具反着指可能腕子就到极限了。

如果实验发现"ρ 在舒适带内但跟踪失败"的情况频繁出现（统计 P(跟踪失败 | ρ ∈ [0.35, 0.85])），可以升级到 4D 表：

| 维度           | 含义              | 分辨率 | 格数 |
| -------------- | ----------------- | ------ | ---- |
| 位置方向水平角 | 目标在肩膀的左/右 | 5°    | 72   |
| 位置方向俯仰角 | 目标在肩膀的上/下 | 5°    | 36   |
| 工具指向水平角 | 工具指向左/右     | 15°   | 24   |
| 工具指向俯仰角 | 工具指向上/下     | 15°   | 12   |

总格数 72×36×24×12 ≈ 75 万，存储 3MB。建表方法完全一样，只是多了两个角度维度，采样量增加到 4000 万（保证每格有足够样本）。运行时用 4D 多线性插值（16 个角点加权平均），成本和 2D 的 grid_sample 同量级。

**默认先用 2D 表**。有数据说有问题再切到 4D，代码改动极小。

## 5. 在线 Base 前馈：用几何计算替代学习

这是本项目相对原方案最大的改动，也是论文的核心贡献之一。

### 5.1 核心问题

base 应该跟着末端轨迹一起移动，使得机械臂始终处于舒适的工作状态。之前的方案试图让 RL policy 自己学会"base 该往哪走"——这需要复杂的课程设计（authority handover、scripted 随机游走）和精心的 reward shaping。

但"base 该往哪走"其实是一个纯几何问题：**如果我想让 ρ 等于舒适值 ρ*，肩膀应该在哪？**

### 5.2 解析计算

对一个目标点 p_tgt，理想的肩膀到目标距离是 ρ* · R_max(u)。所以理想的肩膀位置在"从 p_tgt 出发、沿当前肩膀方向后退这么远"的地方：

```python
def ideal_shoulder(p_tgt, p_sh_current, R_max_table, rho_star=0.6):
    d = p_tgt - p_sh_current
    r = norm(d)
    u = d / r
    r_ideal = rho_star * R_max(u)          # 理想距离
    p_sh_ideal = p_tgt - u * r_ideal       # 理想肩膀位置
    return p_sh_ideal
```

从理想肩膀位置到理想 base 位置，减去 T_mount（肩膀在 base 上的固定安装偏移）。

对多个 preview 点（未来轨迹上的采样点），取加权平均——近处权重大（马上要执行），远处权重小（只看趋势）：

```python
def online_base_nom(s_current, gamma, T_mount, R_max_table,
                     p_sh_current, rho_star=0.6):
    # 沿路径向前采若干点，近密远疏
    Delta = L_h * tensor([0.02, 0.05, 0.10, 0.18, 0.30, 0.45, 0.65, 0.85, 1.0])
    s_k = (s_current + Delta).clamp(max=L)
    p_k = gamma.p_at(s_k)                               # (K,3)

    # 每个点的理想 base 位置
    for each p_tgt in p_k:
        p_base_ideal = ideal_shoulder(p_tgt, p_sh_current, ...) - T_mount

    # 指数衰减加权平均
    weights = exp(-2.0 * Delta / L_h)
    weights = weights / weights.sum()
    p_base_target = weighted_average(p_base_ideals, weights)

    # v_ff = 朝目标 base 位置走
    v_ff = (p_base_target - p_base_current) / T_response
    return v_ff
```

**对计算出来的 v_ff 做低通滤波**，截止频率设在腿的带宽附近（~1.5Hz）。原因：如果 EE 轨迹在两个远距离点之间快速来回，算出的 v_ff 会高频大幅波动，腿跟不上。滤波把高频分量留给 Δv 去学。

### 5.3 这解决了什么

| 原来的问题                              | 现在怎么解决                              |
| --------------------------------------- | ----------------------------------------- |
| 训练时 v_ff 依赖逆向生成器，评测时没有  | 在线计算，训练和评测完全一致              |
| 需要 authority handover（α 从 0 到 1） | 不需要，v_ff 从第一天起就是正确的前馈方向 |
| 需要 v_scripted 随机游走来给早期探索    | 不需要，v_ff 本身就在动                   |
| 需要逆向生成器保证轨迹可行              | 任何轨迹都可行（base_nom 总有解）         |
| 课程 3 轴 (A, B, α)                    | 课程 2 轴 (A, B)                          |

### 5.4 v_ff 不告诉 policy "怎么走"

v_ff 是一个速度向量（"往右前方走 0.3m/s"）。它**没有**告诉 policy：

- 要不要降低 base 高度（posture）
- 要不要改步频
- 动力学上怎么实现这个速度
- 这些决策之间怎么协调

这些维度的耦合只能靠学习解决。policy 学的是"怎么走"，而不是"往哪走"。

### 5.5 yaw（朝向）的处理

v_ff 给出的是 xy 平移速度。base 的朝向（yaw）用简单规则：沿运动方向转。如果轨迹要求侧向移动（EE 在机器人正侧方），yaw 对齐 preview 窗口内目标的平均方向。

## 6. 未来可达性 Profile：让 base 提前行动

### 6.1 ρ_k profile

如果 base 只看当前 ρ 来决定是否移动，通常会反应太晚（ρ 已经快出界了才开始动，但 base 的响应需要几百毫秒）。

解决办法：提前查看后续轨迹，计算"如果 base 保持当前位姿不动，后续各点的 ρ 是多少"。

```python
rho_k = rho( gamma_p(s_k) ; T_base(now) )    # 冻结 base 假设
```

这给出一条 K 维的曲线：ρ 在未来各 preview 点的值。如果曲线快速上升 → base 必须尽快开始移动。

冻结 base 假设的好处：

- 只需当前状态，不依赖任何预测
- 定义上不含 EE 当前位置 → 和 EE 误差正交 → 不会导致极限环
- 训练和评测的计算完全一致

### 6.2 从 profile 中提取摘要量

让 MLP 从 K 维向量里自己解出"第一个越界点在哪"是非平凡的，不如直接算：

```python
urgency   = max(rho_k - rho_hi, 0).max()           # 视界内最大超标量
s_to_viol = 第一个 rho_k > rho_hi 的点到当前的距离  # 没有越界则 = 1
```

两个标量，零成本，收益大。

### 6.3 preview 点按路径距离采样

如果按时间采样（"0.5 秒后的目标在哪"），policy 减速时 preview 的空间覆盖范围也缩短——本来更需要提前规划，反而只能看到更近的轨迹。

按路径距离采样避免了这个问题。无论走多快，policy 始终能看到前方同样长度的轨迹。

近处密、远处疏：马上要执行的轨迹需要精确信息，远处只需要大致趋势。

### 6.4 当前 ρ 用于 reward，未来 profile 只用于观测

```
reward: 只惩罚当前点 ρ0 的 barrier（§4.4）
观测:   完整 ρ_k 向量 + urgency + s_to_viol
```

**不要把未来的 ρ_k 加进 reward。** 那是 value function 的职责——它本来就在估计"未来 ρ 惩罚的折扣和"。在 reward 里手写一份未来惩罚 = 双重计算，会导致 policy 过度保守。

## 7. 训练轨迹的生成

### 7.1 正向生成 + 事后标注难度

有了在线 base_nom，轨迹生成大幅简化。不再需要逆向生成器（先采 base 路径再在管道内采 EE）。

流程：

```python
def generate_and_label():
    # 1) 正向随机生成 EE 轨迹，完全自由
    gamma = random_ee_trajectory(f_max=..., v_max=..., ...)

    # 2) 对这条轨迹跑一遍在线 base_nom，得到隐含的 base 运动需求
    v_base_implied = 沿路径计算 base_nom 的导数
    a_base_implied = v_base_implied 的导数

    # 3) base 运动需求就是难度标签
    difficulty = {
        'v_base_max': max(||v_base_implied||),
        'a_base_max': max(||a_base_implied||),
    }

    # 4) 按难度筛选
    if difficulty 在当前课程等级范围内:
        return gamma, s_ref, difficulty
```

原来拒绝采样拒绝的是"可行性"（高难度时接受率暴跌）。现在拒绝的是"难度等级"（任何轨迹都可行，只挑难度匹配的），接受率稳定。

### 7.2 所有难度等级都要有 base 运动

即使是最低难度等级，也让 EE 目标缓慢漂移（~3 cm/s），使得 base 必须慢慢跟上。这保证 policy 从第一天起就有"动 base"的经验。

```python
drift_speed = 0.03      # m/s，很慢
drift_direction = random_unit_vector_xy()
p_target(t) = p_local(t) + drift_direction * drift_speed * t
```

课程升级 = 漂移速度和加速度逐步增加。没有"先不动 base → 突然要动"的跃变。

### 7.3 全 SE(3) 姿态生成

因为是全 SE(3) 跟踪，姿态必须显式生成。两种模式混合：

| 模式            | 含义                                                   |
| --------------- | ------------------------------------------------------ |
| tangent-aligned | R(s) 的某轴跟随路径切线方向，类似"沿路径拖动工具"      |
| independent     | R(s) 是独立的带限 SO(3) 随机游走，覆盖"位置不动只转腕" |

### 7.4 动捕轨迹是评测集，不是训练集

动捕轨迹不该拿来训：它带着人臂的形状先验和人手的动力学时序，和机器人的工作空间不匹配。

正确用法：

1. 训练用合成轨迹
2. 测量动捕轨迹集的功率谱，把课程的 f_max 目标设在其 95 分位之外
3. 动捕原样进 held-out 评测集

| 步频 / swing height |                                      | 限速                              |
| FF 通道             | 未来 CoM 偏移 / 惯量 → 腿           | —                                |

**动作尺度必须分组**。臂和腿的惯量、减速比差一个量级，不能用统一的 action scale。

### 8.3 Reward（分组，multi-critic）

**先解释什么是 multi-critic，以及为什么需要它。**

在标准的 Actor-Critic 强化学习里（PPO 就是这一类），除了 policy（决定做什么动作，也叫 actor）之外，还会训练一个 **value function**（也叫 critic）。critic 的作用是预测"从当前状态出发，未来能拿到多少折扣累积 reward"。训练时用 critic 的预测值去计算 **advantage**（这一步动作比平均水平好多少），policy 根据 advantage 的正负来调整——advantage 为正就增加这个动作的概率，为负就减少。

通常整个系统只有**一个** reward 标量、**一个** critic。但本项目的 reward 明显分成三类性质完全不同的目标：

- Group T 关心"有没有跟上轨迹"
- Group R 关心"机械臂构型舒不舒服、有没有在替 base 干活"
- Group S 关心"动作平不平滑"

如果把这三组加权求和成一个标量塞给一个 critic，会出现一个具体的问题：**这三组 reward 的量级和"难易程度"不一样**。比如 Group T 的进度奖励几乎每一步都能拿到（容易学），Group R 的可达性惩罚只在临界状态才出现（难学、稀疏）。如果混成一个数，critic 主要学的是量级大、频率高的那部分（往往是 Group T），Group R 的信号会被淹没——policy 学出来的行为可能是"精度很好，但机械臂经常在极限位形工作"，因为可达性方面的负梯度太弱了。

**Multi-critic 的做法**：给三组 reward 各配一个独立的 critic（三个 value head），分别预测各自的未来累积值。算 advantage 时，每组各自算完之后再各自做 normalize（减均值除标准差），这样每组 advantage 的量级都被拉到同一个尺度，谁也不会淹没谁。最后把三组 normalize 后的 advantage 加权求和，喂给 policy 更新。

用一个类比理解：这相当于给学生请了三个各管一科的老师（跟踪、协调、平滑度），而不是一个老师看一个总分——总分老师容易只盯着最容易拿分的那一科，分科老师能保证每一科都被认真对待。

三个 critic 共享 policy 网络的底层特征提取层，只有最后的输出头不同，所以不算增加太多参数和计算量。

**Group T — Tracking（跟踪精度）**

```
+ w_p · ṡ                              进度（鼓励沿路径前进）
− w_e · d_lat                           横向误差（离路径多远）
− w_t · deadzone(timing_err, τ)         时间误差（死区宽度 = τ）
− w_v · ‖twist_err‖                    速度跟踪
```

**Group R — Reachability / 构型（可达性与协调）**

```
− w_ρ · barrier(ρ0; ρ_lo, ρ_hi)        双边软 barrier
+ w_m · manipulability                  可操作度（奇异逃逸压力）
− w_l · joint_limit_barrier             关节限位距离
− w_ema · ‖ema_dq‖                     臂的低频出力惩罚（§9.1 详述）
− w_rr · |dρ/dt|                        ρ 变化率惩罚（§9.2 详述）
```

**Group S — Smoothness / 正则（平滑性）**

```
− action rate（动作变化率）
− Δq 幅值
− q̈_arm（臂关节加速度）
− posture cmd rate（防止 posture 被当高频通道用）
− Δv 幅值（鼓励信任 v_ff，§9.3 详述）
```

> **绝不添加**：base orientation penalty / base height penalty。那是在惩罚自己的命令通道（§1.2）。

**Multi-critic**：Group T / R / S 各自一个 value head，各自 normalize advantage，在 policy gradient 层加权。这比手调 20 个系数稳健得多。

### 8.4 终止条件

- d_lat > d_max（横向误差过大，投影失去意义）
- |timing_err| > e_max（严重落后）
- IK 分支跳变（不让不连续样本污染 buffer）
- base 摔倒 / 自碰

## 9. 协调性 Reward：激励正确的 base-arm 分工

这一节解决的问题是：现有的 reward 结构下，"base 不动 + 臂拼命伸"和"base 合理跟随 + 臂轻松补偿"可能得到差不多的 reward——因为没有任何一项直接说"能用 base 解决的就不要用臂"。

### 9.1 惩罚臂的低频出力

好的 base-arm 协调有一个可观测的特征：**臂只做高频的小幅修正。** 如果臂的关节运动里出现了低频的、持续性的偏移，那说明有一个"慢问题"本该由 base 处理，但 base 没处理，臂在替它扛。

用指数移动平均（EMA）提取 Δq 的低频分量：

```python
# 每一步更新
ema_dq = alpha * ema_dq + (1 - alpha) * dq_arm
# alpha ≈ 0.95，时间常数 ≈ base 的响应时间（0.3-0.5s）
```

- 臂做高频来回摆动（步态补偿）→ EMA 正负抵消 → 不罚
- 臂持续往一个方向伸（替 base 干活）→ EMA 累积 → 罚

```python
r_effort_alloc = -w_ema * norm(ema_dq)
```

**ema_dq 同时进入 reward 和观测。** 进观测的原因：policy 通过它知道"我的臂已经在替 base 干活了"，可以主动调整 base。

### 9.2 惩罚 ρ 的变化率

ρ 的 barrier 只管"别出界"。但好的协调意味着 **ρ 应该稳定**，不应该大幅波动。ρ 波动说明 base 没有平稳地跟随目标。

```python
r_rho_rate = -w_rr * abs(rho0 - rho0_prev) / dt
```

为什么惩罚变化率而不是惩罚偏离 ρ*：有些轨迹的几何决定了 ρ 不可能恒定。惩罚变化率允许 ρ 平缓变化，但不容忍突然跳动。

### 9.3 惩罚 Δv 幅值

在 v_ff 已经给出了合理前馈的前提下，Δv 应该很小。惩罚 Δv 幅值鼓励 policy 信任 v_ff，只做必要的修正。

```python
r_dv_small = -w_dv * norm(delta_v)
```

权重给小。这是一个柔性约束，不是硬限制。

### 9.4 三个信号的配合

| 信号     | 从什么角度看协调           | 进 reward | 进观测 |
| -------- | -------------------------- | --------- | ------ |
| ema_dq   | 关节空间：臂在做 base 的活 | ✅        | ✅     |
| dρ/dt   | 任务空间：base 没稳定住    | ✅        | —     |
| Δv 幅值 | 控制空间：没信任前馈       | ✅        | —     |

三个角度互补，任何一个因特殊情况失灵时，另外两个还能抓住问题。

## 10. 安全滤波器：部署期的兜底保护（可选）

### 10.1 动机

policy 在合成轨迹上训练，demo 用的是动捕随手画的轨迹——这是分布外测试。policy 对 base 的预判可能出错，ρ 冲出舒适带，臂进入奇异邻域，EE 精度突然崩一下。

安全滤波器在 policy 输出和执行之间加一道检查：如果执行这个动作会让 ρ 越界，做最小修正。正常时完全不干预。

### 10.2 原理

ρ 对 base 的位姿和 posture 命令是可微的（§4.5）。我们可以算出"如果执行动作 a，ρ 会怎么变"：

```
ρ̇ = (ρ 因目标运动的变化，控制不了) + (∇ρ · ξ̇(a)，可以通过改 a 来控制)
```

约束条件（CBF 风格）：

```
ρ 的增速 ≤ κ × (ρ_hi − ρ)      # 离上界越近，允许的增速越小
```

如果动作 a 违反约束 → 沿梯度方向做最小投影，刚好不越界。不违反 → 原样放行。

### 10.3 防抖

在激活阈值上加滞回（越界 0.02 才开、回到带内 0.05 才关），修正量过一阶低通。

### 10.4 配套

把滤波修正量 `a_filtered − a_original` 喂回观测，并在训练最后阶段把滤波器挂进仿真环路。

**这是一个可删模块。** 先做 ablation，有效才进正文，无效删掉不影响主线。

## 11. 课程学习

### 11.1 不再需要 authority handover

有了在线 v_ff，最复杂的课程机制被去掉了。不再需要：

- α 从 0 到 1 的渐进移交
- v_scripted 随机游走
- "先锁 base 再解锁"的阶段切换

### 11.2 两个独立的难度轴

| 轴                               | 含义                             | 早 → 晚                  |
| -------------------------------- | -------------------------------- | ------------------------- |
| **A: base 运动需求**       | 轨迹隐含的 v_base_implied 的幅度 | 慢漂移 → 全速移动        |
| **B: 时序带宽 + 时间约束** | f_max + τ 采样范围              | 准静态/τ=∞ → 高频/τ=0 |

A 的标签来自在线 base_nom 的导数（§7.1），B 的标签来自轨迹生成参数。

### 11.3 网格推进

仿 legged_gym terrain curriculum：每个 (A, B) cell 记录成功率，成功升级、失败降级。机器人在网格里游走。不把 A 和 B 压成一维——那会人为规定穿越顺序，可能不是最优的。

### 11.4 抗遗忘

保持跨全部已解锁等级的混合采样：60% 当前前沿 + 40% 从历史等级均匀采。纯移动前沿会让 policy 忘掉简单情况——测试时简单轨迹占多数，这会直接导致失败。

### 11.5 Reachability reward 从第一天起就给

即使最简单的等级、base 几乎不需要移动，reward 里也要有 ρ barrier + manipulability + EMA 惩罚。作用：

- 早期学到的不是"够到就行"，而是"够到 + 保持余量 + 不用臂替代 base"
- 后续难度提升时，"余量不足"和"臂在替 base 干活"的负梯度**已经存在于 value function 里**了 → base 通道一有需求立刻有信号

### 11.6 完整流程

```
Phase 0  腿: 带臂重训剪裁版 WTW
         · gait 固定 trot + 全 posture + 步频/swing height
         · 臂运动激进随机化 + payload 随机化
         · posture 命令范围放宽（WTW 原范围对 loco-manip 太窄）
         · + 响应一致性 reward（§2.3）
         · + 臂 FF 通道（§2.4）
         · 反向输出: gait phase / contact / base 预测 / (v_act−v_cmd)
         → 冻结
         注意：WTW 现成 checkpoint 不能直接用——没经过带臂训练

Phase 1  上层 policy 训练
         · v_ff = 在线 base_nom（§5），Δv 限幅从小到大
         · 所有等级都带慢漂移（§7.2）
         · τ 随机采样喂进观测（§3.6）
         · reward: Group T + Group R（含 EMA + ρ rate）+ Group S
         · 难度网格 (A, B) 自动推进，混合采样抗遗忘
         · [可选] 后期挂入安全滤波器
```

> 没有 Phase 2、Phase 3。就一个 phase，难度连续爬。

## 附录 A：论文故事脉络

### A.1 一句话贡献

"我们证明四足 loco-manipulation 中 base 与机械臂的运动协调可以从可达性几何中解析地计算，而不需要作为 RL 的学习目标。基于此，我们提出了一个 whole-body SE(3) 轨迹跟踪系统，其 base 前馈、轨迹课程和 effort allocation reward 均从同一个可达性模型推导而来，对任意未见过的轨迹即时可用，无需重新训练。"

### A.2 故事的五层结构

**第一层：问题定位——为什么现有工作不 general**

四足机械臂做末端轨迹跟踪，现有工作都卡在 base 协调上：

- RoboDuet：base 由人遥控，系统不解决 base 去哪的问题
- ETH pose tracking：base 静止，回避了协调问题
- UMI-on-Legs：协调隐含在 per-class 训练里，换轨迹得重训
- 端到端单 policy：base 运动靠 RL 涌现，需要大量课程工程

所有人都把 base 协调当成需要学习的难题。但 loco-manipulation 和 locomotion 有根本区别：locomotion 的扰动来自不可观测的外部世界（地形、摩擦），必须靠学习应对；loco-manipulation 的"扰动"来自已知的自身运动学——臂在哪、多长、目标去哪，全部已知。

**核心 insight：既然耦合是已知的，base 运动就应该被计算出来，而不是被学习出来。**

**第二层：base 运动的解析生成（方法核心）**

对任意末端轨迹，纯几何计算即时给出 base 的前馈速度 v_ff——让机械臂始终处于舒适构型。不依赖训练，不依赖轨迹生成方式，对合成/动捕/任意来源的轨迹即时可用。

这一步同时解决了三个原来很难的问题：训练-评测一致性（不再依赖逆向生成器）、课程简化（不需要 authority handover）、轨迹生成简化（正向采样 + 事后标注）。

**第三层：轨迹表示与时间约束的统一**

γ(s) + s_ref(t) 分解让空间和时序难度正交可调。τ 条件化让同一 checkpoint 覆盖从纯路径跟随到严格时间跟踪的整个连续谱。

**第四层：协调性 reward——频率域的 base-arm 分工**

通过惩罚臂关节速度的低频分量（EMA），显式激励"低频大位移交给 base，高频小修正留给臂"的分工。配合 ρ 变化率惩罚和 Δv 幅值惩罚，三个角度互补。

**第五层：评测——闭环带宽作为核心指标**

扫频 → EE 幅频曲线，一条曲线概括系统跟踪能力。误差频谱同时是诊断工具。Demo 选择让 general、时间律、姿态三个约束各自物理化。

### A.3 每个贡献对应的 ablation

| 贡献                         | ablation 对照                       | 预期差异                                                |
| ---------------------------- | ----------------------------------- | ------------------------------------------------------- |
| 解析 v_ff vs 学习 base 运动  | 去掉 v_ff，让 policy 直接输出 v_cmd | base 利用率大幅下降；或需要 authority handover 才能收敛 |
| τ 条件化 vs 固定 τ=0 训练  | 固定 τ=0 训练，评测时扫 τ         | Pareto 曲线退化（固定训的 policy 不会利用宽松度）       |
| EMA 低频出力惩罚 vs 不加     | 去掉 EMA 惩罚                       | 误差频谱低频分量更高；base 利用率更低                   |
| 4D 可达表 vs 2D 表 vs 球近似 | 三档对比                            | 舒适带内失败率递减                                      |
| 安全滤波器 开 vs 关          | 关闭滤波器                          | worst-case 误差尖峰更大；ρ > ρ_hi 次数更多            |

### A.4 叙事主线

"Locomotion 的主线是在不可观测的外部世界里保持鲁棒；loco-manipulation 的主线是在已知的自身动力学里维持精度。我们把这个认知贯彻到底：用可达性几何解析计算 base 的前馈运动（by construction, not by training），用频率域 reward 激励正确的 base-arm 分工，用 τ 条件化统一路径跟随和时间跟踪。结果是一个对任意 SE(3) 轨迹即时可用、无需重训的 whole-body 控制系统。"
